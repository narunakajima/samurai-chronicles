# /learn-analytics — 学習版（英語で聴く日本史）YouTube アナリティクス分析

学習版チャンネルの視聴データから、「どの回が、どこで離脱され、どこから見つけられているか」を把握し、
制作ルール（台本の長さ・導入・公開時刻・サムネイル・ショートの訴求）に反映するコマンド。
2026-10-25 追加。SC の `/sc-analytics` と同じ考え方で、**月1回程度**。公開直後の数日分は、データが遅れて出るので、
最初の本格的な分析は、**3回分以上が公開されて2週間後**（2026-11 中旬以降）を目安にする。

学習版は、本編が約55〜60分と長い。SC と違い、**視聴の維持率の曲線（どこで離脱するか）が最重要**。
SC のデータ（`sc_yt_analyze.py`）とは別のチャンネル・別のデータ。混ぜない。

---

## STEP 1 — データ最新化

```bash
cd learning && python3 learn_yt_reporting.py download
```

Reporting API のレポート（インプレッション・CTR・年齢性別）を、Drive の `analytics_learning/raw/` に差分で保存する。
**取得は欠かさず行うこと**（古いレポートは一定期間で消える）。ジョブは 2026-10-25 に登録済み（`learn_yt_reporting.py status` で確認）。
`invalid_grant` が出たら、`python3 learn_yt_reporting.py auth` で再認証する（ブラウザで許可。プロジェクトは「本番環境」なので、失効は起きにくい）。

## STEP 2 — 集計

```bash
cd learning && python3 learn_yt_analyze.py             # 回ごとの一覧・ショート・流入・国・維持率
cd learning && python3 learn_yt_analyze.py --json      # 解釈用（STEP 3 で Opus に渡す）
```

見る指標と、見方:
- **維持率の曲線:** 動画の長さの何割の所で、何割が残っているか。**急に落ちる地点**（導入のあと・特定のシーン・通しの始まり）を探す。
  導入は、2026-10-24 から短くした（ep113 以降）。ep106（導入が長い）との比較で、効果を見る
- **平均視聴率・平均視聴時間:** 長い動画なので、平均視聴率は低くなるのが普通。回どうしの差を見る
- **CTR（サムネイルのクリック率）とインプレッション:** サムネイルの文言（英文の長さ・主人公）の効果。ep115 のように英文を短くした回との比較
- **流入経路:** 検索・関連動画（ショートからの関連動画）・ブラウズ・外部。ショートの関連動画設定が効いているか
- **国:** 日本の割合（ターゲットは日本語話者）。日本以外が多ければ、タイトル・説明の見直し
- **登録者の増え方:** 回ごと。ショートと本編のどちらから増えているか
- **公開時刻（07:00）:** 日別の視聴と、公開日の立ち上がりを見る（時間帯別は YouTube Studio の「視聴者がオンラインの時間帯」を、ユーザーに見てもらう）

注意: 回数が少ないうちは、**差が偶然かもしれない**。1〜2本の差で、ルールを変えない（SC の月次分析でも、少数の差を過大に解釈した実例がある）。

## STEP 3 — 解釈と提案は Opus に任せる

`--json` の出力と、`CLAUDE.md` の「学習版」の節、`learning/lessons/` の台本（導入・構成）を渡して、
**Opus のサブエージェント**（`model: "opus"`、`subagent_type: "general-purpose"`）に、解釈と提案を書かせる。
依頼に必ず書くこと: ①データの遅れ（2〜3日）と、回数の少なさ ②「少数の差は結論にしない」 ③提案は、台本・導入・公開時刻・サムネイル・ショートの
どれを、どう変えるかまで具体的に ④変えるべきでない決定事項（学習版の構成、字幕のレイアウト、7時公開などは、ユーザー決定）。

## STEP 4 — 報告と反映

- ユーザーに、要点（良かった点・離脱の多い地点・提案）を日本語で報告する。**ルールの変更は、ユーザーの確認を取ってから** `CLAUDE.md` の「学習版」の節に反映する
- 分析のメモが必要なら `learning/analytics_notes/`（なければ作る）に日付つきで残す
