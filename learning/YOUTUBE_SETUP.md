## 2. 電話番号の確認 🧑

学習版の本編は**約55分**ある。YouTube では、確認していないチャンネルは**15分を超える動画をアップロードできない**。
また、**独自のサムネイル**を設定するのにも確認が必要。

1. 新しいチャンネルに切り替えた状態で、YouTube Studio →「設定」→「チャンネル」→「機能の利用資格」を開く
2. 「電話による確認が必要な機能」で、電話番号の確認をする（SMS などでコードが届く）
3. 「長時間の動画」「カスタム サムネイル」が使える状態になったことを確認する

> ブランドアカウントのチャンネルごとに必要かどうかは、画面の表示に従ってください。

> ⚠️ **1つの電話番号で確認できるのは、1年に2チャンネルまで**（YouTube 公式ヘルプ「Verify your YouTube account」、2026-10-23 確認）。
> Samurai Chronicles・ランプの独り言・Kagaku-Life などで、過去12か月に同じ番号を2回使っていると、
> 「この電話番号はすでに作成できるアカウント数の上限に達しています」と出て確認できない。その場合は別の電話番号を使う。

## 4. Google Cloud プロジェクトと API の準備 🧑

### 4-1. プロジェクトを分けるか

YouTube Data API には、プロジェクトごとに**1日のクォータ（使える量）**がある（既定は 10,000 ユニット/日）。
動画1本のアップロードで約1,600ユニット使う。

| 案 | 内容 | 評価 |
|---|---|---|
| **A. 学習版専用のプロジェクトを新しく作る** | クォータが本編（SC）と分かれる | **おすすめ**。本編は 2026-09 に「クォータを他と共有しないため」専用プロジェクト（SC Project）に分けた経緯があり、同じ考え方 |
| B. 本編の SC Project を共用する | 新しい設定が少ない | 1回の公開で本編側 約3,300、学習版側 約3,300 ユニットを使い、同じ日に重なると上限に近づく |

以下は **A（新しいプロジェクト）** の手順。

> ✅ **作成済み（2026-10-23）:** プロジェクト名 `SC Learning`、プロジェクト ID `sc-learning-512503`（プロジェクト番号 560944546631）。組織なし。

### 4-2. プロジェクトを作る

1. https://console.cloud.google.com/ に naru.nakajima@gmail.com でログインする
2. 上部のプロジェクト選択 →「新しいプロジェクト」→ 名前（例: `SC Learning`）で作成する

### 4-3. YouTube Data API v3 を有効にする

1. 作ったプロジェクトを選んだ状態で、「API とサービス」→「ライブラリ」
2. 「YouTube Data API v3」を検索 →「有効にする」

### 4-4. OAuth 同意画面を設定する

1. 「API とサービス」→「OAuth 同意画面」（画面によっては「Google Auth Platform」→「ブランディング」「対象」）
2. ユーザーの種類: **外部**
3. アプリ名（例: `SC Learning Uploader`）、サポートメール、デベロッパーの連絡先に naru.nakajima@gmail.com を入れる
4. スコープはここでは追加しなくてよい（スクリプトが認証のときに求める）
5. テストユーザーに naru.nakajima@gmail.com を追加する
6. **公開ステータスを「本番環境」にする**

> ✅ **実際にやってみて分かったこと（2026-10-23）:** 「アプリを公開」のボタンは、最初は灰色で押せなかった（「ブランディングの構成を完了する必要があります」）。
> 必須の項目（アプリ名・サポートメール・連絡先メール）を入れただけでは足りず、ブランディングの **アプリケーションのホームページ（`https://www.samurai-chronicles.com/`）・
> プライバシーポリシーのリンク（`https://www.samurai-chronicles.com/privacy`）・承認済みドメイン（`samurai-chronicles.com`）** を入れたら押せるようになった。
> **ロゴはアップロードしない**（アップロードすると、Google の確認〔審査〕が必要になる）。
> OAuth クライアント ID の作成画面にある「**Use this client for an AI-powered agent**」は、公式の説明が「Google の MCP ツールを使う場合に選ぶ」なので、**チェックしない**。

> **なぜ「本番環境」にするか:** 「テスト中」のままだと、認証の有効期限（リフレッシュトークン）が**7日で切れ**、
> 毎週ブラウザで認証し直すことになる。自分だけで使う場合は、Google の審査を受けなくても使える
> （認証のときに「このアプリは Google で確認されていません」という警告が出るので、「詳細」→「（アプリ名）に移動」で進む）。
> 本編の SC Project も同じ設定になっているか、🤖 が確認する。

> ✅ **作成済み（2026-10-23）:** クライアント名 `learn-uploader`（デスクトップ アプリ）。JSON は `~/.claude/secrets/yt_client_secrets_learn.json` に置いた（Drive や ダウンロードフォルダには残さない）。
> MacBook で操作して、Claude Code は iMac で動いているので、ファイルは Google Drive 経由で iMac に渡し、iMac 側で所定の場所に移して、Drive からは消した。

### 4-5. OAuth クライアント ID を作る

1. 「API とサービス」→「認証情報」→「認証情報を作成」→「OAuth クライアント ID」
2. アプリケーションの種類: **デスクトップ アプリ**、名前は任意
3. 作成後に表示される「JSON をダウンロード」でファイルを保存する
4. そのファイルを、次の名前で置く（🤖 に「ダウンロードした」と伝えれば移動する）:

```
~/.claude/secrets/yt_client_secrets_learn.json
```

> このファイルは秘密情報。リポジトリ（git）には入れない（`~/.claude/secrets/` はリポジトリの外）。

## 5. 初回の認証（トークンの作成） 🧑＋🤖

1. 🤖 がアップロード用スクリプトの認証部分を実行する（ブラウザが開く）
2. 🧑 Google のアカウント選択画面で、**新しいチャンネル（ブランドアカウント）の名前を選ぶ**
   - ⚠️ **個人のアカウントや Samurai Chronicles を選ばないこと**。ここで選んだチャンネルにアップロードされる
3. 🧑 「確認されていないアプリ」の警告が出たら、「詳細」→「（アプリ名）に移動」
4. 🧑 YouTube の管理とアップロードの許可を求められるので、「許可」
5. 🤖 認証の結果を `~/.claude/secrets/yt_token_learn.json` に保存し、API でチャンネル名と ID を取得して、
   新しいチャンネルで認証できたことを確認する（違うチャンネルなら、トークンを消してやり直す）

## 6. アップロード用スクリプト 🤖

**作成済み**: `learning/learn_upload.py`（本編の `sc_sns_up.py` と同じ作り方）。`--dry-run` でタイトル・説明・チャプター・素材を確認でき、認証は `--auth-only`。

| 項目 | 内容 |
|---|---|
| 認証 | `yt_client_secrets_learn.json` / `yt_token_learn.json`。毎回、認証したチャンネルの ID が学習版チャンネルか確認し、違えば止まる |
| アップロードするもの | 学習版の本編（mp4）＋サムネイル、ショート（mp4、タイトルに #Shorts） |
| タイトル・説明文 | 回ごとに台本（`lessons/ep{NNN}.json`）から作る。説明文にはチャプター（`build/ep{NNN}/chapters.txt` の各パートの開始時刻）と、SC 本編（英語版）へのリンクを入れる |
| 設定 | カテゴリ「教育」、言語「日本語」、子ども向けではない、タグ |
| 公開 | **予約投稿**（公開日時を指定）。即時公開は、指示があったときだけ |
| 記録 | アップロードした動画の ID と予約日時を、台本の JSON（または別の記録ファイル）に残す |

**クォータの目安（1回あたり）:** 本編のアップロード 約1,600 ＋ サムネイル 50 ＋ ショート 約1,600 ＝ **約3,300ユニット**
（1日 10,000 ユニットに十分収まる）

**API ではできない（と思われる）こと:**
- ショートの「関連動画」（ショートの画面から本編に飛べるリンク）の設定。
  API でできるかは 🤖 が確認する。できなければ、アップロード後に 🧑 が YouTube Studio で設定する（1本あたり1分ほど）

### 試験のしかた
1. ep106 の本編・ショート・サムネイルを、**非公開**でアップロードする
2. 🧑 YouTube Studio で、タイトル・説明文・チャプター・サムネイル・ショートの表示を確認する
3. 問題がなければ、予約投稿に切り替える

## 7. `/sc-learn` に組み込む 🤖

## 8. 公開前に確認すること 🧑＋🤖

収益化は将来の目標なので、今のうちに次を確認しておく。いずれも 🤖 は最新の内容を確認していないので、
