# QA報告の固定形式（SC版・正本）

2026-11-27 制定（handoff 2026-11-27-006）。画像QA・BGM QA・ファクトチェック・最終判定など、SCのあらゆるQA報告はこの形で書く。
手順書（`.claude/commands/*.md`）・担当者の定義には、この形を重ねて書かず、このファイルへの参照だけを置く。
再生成・再試行の上限は `team/qa_limits.json` が正本。

## 形式

QA報告は、対象ごとに次の表を出す。1項目1行。

| チェック項目 | 合否 | 根拠 |
|---|---|---|
| （例）TEXT: 画像内の可読テキスト | 合 / 否 / 保留 | 見たもの（シーン番号・ファイル名・該当箇所・一次資料）を具体的に |

- **合否は「合」「否」「保留」の3値だけ。** 「概ね良好」「おそらく」などは使わない。保留は理由と、誰が何をすれば決まるかを根拠欄に書く。
- **根拠は、見た実物（画像・音声・確認書・一次資料）にもとづく。** 「担当がOKと言った」は根拠にならない。
- 表の下に、1行で総合（`総合: 合 / 否 / 保留`）と、否・保留があれば次の一手（再生成・修正・エスカレーション先）を書く。
- 解説・検討・代替案は、否・保留の次の一手に必要な分だけ。

## 既定のチェック項目

- 画像: MISMATCH / DISTORTION / TEXT / STYLE / ARCHITECTURE / HAIRSTYLE（定義は `sc_image_gen.py` の QA プロンプトが正本。例外は `memory` の各ルール）
- BGM: ボーカル・台詞混入 / オーケストラ純度 / ライセンス表記
- 制作確認書: 史実の裏取り / 容貌 / 年代・時代区分
- 最終判定（sc-manager）: 判定は「完成」「要修正」「要確認」の3つ。理由と、確認した成果物の絶対パスを書く

## 上限に達したとき

`team/qa_limits.json` の上限を超えて同じ工程を繰り返さない。未解決の項目は「否」のまま残し、エスカレーション先
（画像は sc-art-director、それ以外は sc-manager）へ、項目・根拠・試行回数をそのまま渡す。
