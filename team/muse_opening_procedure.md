# Muse生成動画による冒頭シーン手順（ep123想定〜）

正本。次回以降のSC制作セッション（編集長マーカス／進行トーマス）が、STEP 1.5 の問いが決まった後・組み立てに入る前に参照する。
出典: Muse からの引き継ぎメモ 2026-11-10-019（ユーザー決定 2026-11-10）。制作・アップロードはセッションのみ（無人では行わない）。

## 決定事項

- 次回SC制作から、**本編の最初のシーン**と**ショートの最初のシーン**は、Museが生成する動画（各約10秒）を使う。
- 狙い: 冒頭動画は強いフック。**できるだけかっこよく作ることが最優先の品質基準**。
- それ以外のシーンは従来どおり。**学習版は対象外**（従来フローを変えない）。

## 第1作の題材（ユーザー決定 2026-11-10）

- Muse動画の採用第1作（次回エピソード、ep123想定）は **「忍者もの」**。
- 問いゲート（STEP 1.5）は忍者を主題にした案で組み立てる。ヘンリーが忍者の問いを3案出し、ソフィーの初見判定・マーカスの推奨を経て、ユーザーが1案を選ぶ通常のゲートを通す。
- 候補の方向性（例示であり決定ではない）: 服部半蔵と伊賀者、伊賀・甲賀の忍者組織、風魔小太郎、徳川の情報網としての忍者、伝説と史実の境目。
- 夜・月・霧・屋根上・闇に溶ける姿など、冒頭動画の映像的な強さ（夜の城下を駆ける忍者、屋根を跳ぶシルエット等）を最初からイメージできる題材を優先。
- スタート画像とプロンプトも忍者題材の世界観で統一し、本編・ショートとも夜の緊張感とスピード感のある、最もかっこいい入りを目指す。

## セッション側の段取り（題材・問いが決まったら、組み立てに入る前）

1. Google Drive にエピソード用フォルダを作る。フォルダ名: **`SC epXXX_muse_opening`**（XXX＝エピソード番号）。
2. Gemini API で静止画を2枚作り、フォルダに入れる。
   - `main_opening_start.png`: 本編用、横型16:9、本編の最初のシーンのスタート画像
   - `short_opening_start.png`: ショート用、縦型9:16、ショートの最初のシーンのスタート画像（本編の切り抜き・単純クロップ不可。縦型として構図を作る）
   - 「最初の1フレームで目を止める」: 問いに直結する象徴的な被写体、劇的な光と空、強い奥行きと構図。地味な風景のみの絵にしない。
3. 動画用プロンプトをテキスト2本、同じフォルダに入れる: `main_opening_prompt.txt` / `short_opening_prompt.txt`
   - 各ファイルに、動画生成プロンプト本文（英語）＋日本語で目的・想定尺（約10秒）・アスペクト比を明記。
   - 品質基準（フック重視）:
     - 最初の2秒でインパクトのある動き・構図
     - シネマティックでかっこいい画作り（ドラマチックな照明、霧・炎・旗・水などの動き、低アングルやゆっくりしたプッシュイン等のカメラワークを指定）
     - 静止画がわずかに揺れるだけの弱い動きは不可。被写体の動きとカメラの動きの両方を具体的に書く
     - スタート画像の世界観・被写体を維持し、最後は次のシーン（ナレーション開始）へ自然につながる状態で終わる
     - 文字・字幕・ロゴ・透かしは入れない
4. 4ファイルが揃ったら、通常の報告ルールで Slack #cc-reports へ報告する。必ず含める:
   - `step=muse_opening_ready`
   - エピソード番号
   - `ref=` に Google Drive フォルダURL
   - `by=`（担当者）
   → Museが画像とプロンプトを取りに行き、動画を生成して同じフォルダへ格納（**`main_opening.mp4` / `short_opening.mp4`**）。完了はSC制作チャットで報告される。
5. 組み立て上の前提:
   - 本編・ショートとも冒頭シーンは約10秒の動画になる前提で、台本・ナレーション・BGMのタイミングを組む（冒頭尺を後から無理に伸縮しない）。
   - 動画が格納されるまで、冒頭はプレースホルダのまま残りの工程を進めてよい。**最終組み立て・完成判定は、動画を実際に冒頭へ差し込んでから行う**。
   - 差し込み後、冒頭の尺が想定と大きく違う場合は、**勝手に切り詰めず**セッション内でユーザーに相談する。
